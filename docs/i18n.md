# Internationalization

The site ships two locales:

| URL         | `html lang` | Dictionary   |
| ----------- | ----------- | ------------ |
| `/`         | `en`        | `en.json`    |
| `/pt-br/`   | `pt-BR`     | `pt-br.json` |

English is the default locale and has no URL prefix. Locale folders under
`src/pages/` must match the values in `LOCALES` exactly.

## Adding or changing a UI string

1. Add the key to `src/i18n/en.json`.
2. Add the same key to `src/i18n/pt-br.json`, in natural Brazilian Portuguese.
3. Use it through the `t()` helper:

   ```astro
   ---
   import { t } from "../i18n/utils";
   import type { Locale } from "../i18n/locales";

   interface Props {
     locale: Locale;
   }

   const { locale } = Astro.props;
   ---

   <h1>{t(locale, "hero.greeting")}</h1>
   ```

4. Run `npm run check` and `npm run check:content`.

Placeholders such as `{year}` are interpolated with `t(locale, key, { year })`.
Keep a whole sentence in one key so translators control word order; do not
concatenate fragments in components.

## Internal links

- Use `getRelativeLocaleUrl(locale, path)` from `astro:i18n` for static links.
- Use `localePath(locale, pathname)` from `src/i18n/utils.ts` when switching
  locale on the current page. It strips any existing locale prefix and returns
  a directory-style URL.
- `getAlternates(pathname)` returns the canonical path for each locale, used for
  `hreflang` alternates.

URL slugs stay the same in both locales, for example `/projects/` and
`/pt-br/projects/`.

## Checking translations

`npm run check:content` verifies that:

- `en.json` and `pt-br.json` have the same keys;
- no dictionary value is empty;
- JSON files under `src/content/` contain no empty strings or placeholder
  markers (`TODO`, `TBD`, `FIXME`, `XXX`, `[CONFIRM]`, `lorem ipsum`).

`npm run check` type-checks the dictionaries. A key missing from `pt-br.json`
is a TypeScript error because the Portuguese dictionary is typed against the
English keys.

## Adding a locale

1. Add the locale code to `LOCALES` in `src/i18n/locales.ts`.
2. Add its `html lang` value to `LANG_TAGS` and its endonym to `LOCALE_NAMES`.
3. Create `src/i18n/<locale>.json`.
4. Register the dictionary in `src/i18n/ui.ts`.
5. Add the locale to the Astro `i18n.locales` array in `astro.config.ts`.
6. Create the matching folder under `src/pages/<locale>/` with the same page
   routes as the other locales.
7. Run `npm run check`, `npm run check:content`, and `npm run build`.

Components use `t()` and the locale helpers directly, so they do not need to
change when a locale is added.

## Browser language

The static build does not redirect based on `Accept-Language`. URLs are stable
and predictable, and the visible language switcher is always available.
